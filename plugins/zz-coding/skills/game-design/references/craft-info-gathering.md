# Craft 信息收集协议

## 概述

在设计任何方案之前，必须收集足够的约束条件和设计意图。信息收集的目标不是"问完所有问题"，而是**达到可以开始设计 MVP 的信息充分度**。

## 信息收集的四个维度

### 维度1：设计意图（必须）

**核心问题**：这个系统/活动/功能要解决什么问题？

| 问题 | 类型 | 必要性 | 说明 |
|------|------|--------|------|
| 为什么要做这个？解决什么问题或满足什么需求？ | Gate | 必问 | 对应方法论"设计目的必须一句话讲明白" |
| 做完之后，成功的标准是什么？ | Gate | 必问 | 防止"设计给自己玩"——设计者觉得好不算，要定义可衡量的成功 |
| 目标玩家是谁？（全体 / 某个分层 / 新玩家 / 老玩家） | Gate | 必问 | 对应方法论"四维正交分层" |

### 维度2：框架定位（必须）

**核心问题**：这个东西在游戏里处于什么位置？

| 问题 | 类型 | 必要性 | 说明 |
|------|------|--------|------|
| 填入哪个活动槽位？（循环I / 循环II / 循环III / 社交 / 目标活动 / 战令配套 / 新槽位） | Gate | 必问 | 决定活动周期（基准3天）、收入定位、与并行活动的关系。参见 project-context.md 活动排期框架 |
| 与哪些现有系统有资源交互？（资源进/出） | Gate | 条件必问 | 有资源交互时必问；纯独立系统可跳过 |
| 预期的生命周期？（常驻轮换 / 限时活动 / 一次性） | Flag | 建议问 | 影响数值设计和重置策略 |

### 维度3：体验偏好（按需）

**核心问题**：制作人心中对体验有什么预期？

| 问题 | 类型 | 必要性 | 说明 |
|------|------|--------|------|
| 想要什么样的情绪体验？（紧张刺激 / 轻松休闲 / 策略思考 / 社交互动 / 收集成长） | Sense | 建议问 | 直觉判断，AI无法替代 |
| 有没有参考对象？（竞品、自家其他系统、非游戏体验） | Sense | 可选 | 注意：方法论警告"过度参考竞品" |
| 策略复杂度的偏好？（极简单击 / 轻度策略 / 中等策略 / 高策略） | Sense | 建议问 | 对应方法论"UE直觉式清晰" |

### 维度4：约束条件（按需）

**核心问题**：有什么限制？

| 问题 | 类型 | 必要性 | 说明 |
|------|------|--------|------|
| 开发周期/资源约束？ | Flag | 可选 | 影响方案复杂度上限 |
| 技术限制？（引擎、平台、性能） | Flag | 可选 | 影响可用的交互方式 |
| 体力消耗预期？（一轮活动消耗多少体力？3天周期内免费体力能完成几轮？） | Gate | 必问 | 体力是核心货币，消耗量直接决定付费压力和礼包定价。参见核心框架：体力经济 |
| 是否涉及额外付费设计？（除体力/代币礼包外的付费点） | Gate | 条件必问 | 涉及付费时必问，触发 Value 引擎 |
| 付费设计的底线？（纯加速 / 额外次数 / 专属内容 / 无限制） | Gate | 条件必问 | 仅在涉及额外付费时问 |

## 信息收集的执行规则

### 轮次控制

- **最多2轮**，每轮≤3个问题
- 第1轮：聚焦维度1（设计意图）+ 维度2（框架定位）
- 第2轮（如需要）：维度3（体验偏好）+ 维度4（约束条件）

### 提问策略

1. **不要问能从上下文推断的问题**——如果制作人给了足够的初始描述，直接提炼，只确认不确定的部分
2. **提供选项**——每个问题尽可能给 A/B/C 选项，降低回答负担
3. **合并相关问题**——不要把可以一起问的拆成多轮
4. **展示理解**——提问前先展示 AI 对已有信息的理解，让制作人纠正而非从零描述

### 信息充分度判断

**可以开始设计的最低标准**：

```
✅ 设计目的可以一句话说清楚
✅ 目标玩家分层已明确
✅ 在游戏框架中的位置已确认
□  体验偏好已知（可选，可在 MVP 后通过 Sense 问题补充）
□  约束条件已知（可选，MVP 阶段可忽略细节约束）
```

前三项全部满足即可进入 MVP 草稿阶段。

### 信息不足时的处理

| 情况 | 处理 |
|------|------|
| 制作人只给了一句话需求 | 正常进行2轮信息收集 |
| 制作人给了详细 brief | 跳过大部分问题，只确认1-2个不确定点 |
| 制作人说"你来定" | 提供2-3个方向性选项（Gate 问题），让制作人选择 |
| 2轮后仍信息不足 | 基于已有信息生成 MVP，在 MVP 审核阶段通过 Gate 问题补充 |

## 子代理 Prompt 模板

```
你是信息收集专家，负责在设计方案前收集充分的约束条件和设计意图。

## 你的原则
- 不假设，不确定的必须问
- 不啰嗦，能从上下文推断的不问
- 提供选项，降低回答负担
- 展示理解，让制作人纠正而非从零描述

## 已有信息
[制作人提供的初始描述/需求]

## 当前游戏框架
[游戏的核心循环和系统概览，如有]

## 任务
1. 分析已有信息，判断四个维度的覆盖情况
2. 识别缺失的关键信息
3. 生成≤3个问题（按 Gate > Flag > Sense 优先级排序）
4. 每个问题提供 A/B/C 选项

## 输出格式
- 已有信息摘要（展示理解）
- 信息充分度评估（四个维度）
- 问题清单（使用 decision-protocol.md 中的格式）
```

## 输出示例

```markdown
## 信息收集 · 第1轮

**我的理解**：你想为游戏设计一个新的循环1类玩法，主题是 [X]，目标是 [Y]。

**信息充分度**：
- ✅ 设计意图：基本明确
- ⚠️ 框架定位：不确定资源接口
- ❌ 体验偏好：未知
- ❌ 约束条件：未知

---

🔒 Gate 决策 #1
**问题**：这个玩法的核心资源从哪来？
- A) 从核心循环（钓鱼）获取代币，消耗代币进入
- B) 独立入口，有自己的能量/次数系统
- C) 通过其他活动的奖励解锁

🔒 Gate 决策 #2
**问题**：目标玩家主要是？
- A) 全体玩家（包含新手期玩家）
- B) 中期以上的活跃玩家
- C) 特定分层（请说明）

💡 Sense 直觉 #3
**问题**：策略体验上，你更倾向哪种感觉？
- A) 极简单击型——像刮刮乐、转盘
- B) 轻度策略型——像弹珠、拼图
- C) 中度策略型——像 Bingo、Boss战
```
