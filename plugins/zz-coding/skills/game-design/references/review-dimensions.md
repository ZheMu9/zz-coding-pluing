# 审核检查维度（Review Dimensions）

## 概述

6 个检查维度，每个维度由独立子代理（sonnet）执行。主代理根据方案类型选择引擎组合后 Fan-out 分发。

## 引擎裁剪规则

详见 SKILL.md 的「引擎裁剪速查」表。

## 统一输出格式

每个引擎子代理输出必须包含：
- 检查项表格（检查项 | 结论 ✅/⚠️/❌ | 说明）
- 问题清单（带优先级 P0/P1/P2）
- 维度评分（10分制）
- 决策问题（如有 P0，生成 Gate 类型决策问题）

## 统一子代理 Prompt 前缀

每个引擎子代理的 prompt 必须包含：
1. 角色定义（引用本文件对应章节）
2. 方法论来源（引用 producer-methodology.md 对应章节）
3. 审核对象（文档路径）
4. 检查要求（具体检查项）
5. 输出格式（使用本文件统一格式）

---

## 维度1：设计目的检查（Purpose）

### 检查目的

判断方案的设计目的是否清晰、一致、服务目标人群。

> **方法论来源**：制作人审案30秒三层过滤的第一层——"设计目的是否清晰"。
> 制作人原话："设计目的必须能一句话讲明白。越简单的一句话，表示想得越明白。"

### 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 设计目的清晰度 | 方案是否能用一句话说清核心目的？如果需要两段话才能解释清楚，说明还没想明白 | P0 |
| 2 | 模块服务性 | 方案中的每个模块/子系统是否都在服务设计目的？是否存在"为了有而有"的模块？ | P1 |
| 3 | 目标人群明确性 | 是否明确了服务谁？设计目的是否作用于该人群并达成效果？ | P0 |
| 4 | 宏观适配 | 该方案是否符合整体游戏框架的位置和定位？ | P1 |

### 子代理 Prompt 模板

```
你是设计目的检查引擎（Purpose Engine），负责审核策划方案的设计目的清晰度和一致性。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第5章"决策框架"中的"审案30秒三层过滤"。

## 审核对象
[文档路径]

## 检查要求
逐项检查以下内容，给出检查项表格（检查项 | 结论 | 说明）：

1. **设计目的清晰度**：尝试用一句话总结方案的核心目的。如果你做不到，标记为P0问题。
2. **模块服务性**：列出方案中的每个模块/子系统，判断其是否服务核心目的。不服务的标记为P1。
3. **目标人群明确性**：方案是否明确了目标玩家？设计是否针对该人群？未明确标记为P0。
4. **宏观适配**：方案在整体游戏框架中的位置是否合理？不适配标记为P1。

## 输出格式
- 检查项表格
- 问题清单（带优先级 P0/P1/P2）
- 维度评分（10分制）
- 如果存在P0问题，生成一个 Gate 类型的决策问题供制作人判断
```

### 输出格式

```markdown

**一句话目的提炼**：[AI尝试总结的设计目的]

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 设计目的清晰度 | ✅/⚠️/❌ | ... |
| 模块服务性 | ✅/⚠️/❌ | ... |
| 目标人群明确性 | ✅/⚠️/❌ | ... |
| 宏观适配 | ✅/⚠️/❌ | ... |

**问题清单**：
- [P0] ...
- [P1] ...

**维度评分**：X/10

**决策问题**（如有P0）：
[Gate 格式的决策问题]
```

### 边界条件

- 探索性/实验性方案：允许设计目的模糊，结论标注"低置信度"
- 纯技术方案（如架构重构）：跳过"目标人群"检查项

## 维度2：情绪节奏分析（Rhythm）

### 检查目的

判断方案的情绪曲线是否有波峰波谷设计，是否存在"情绪平原"（长时间无情绪波动的段落）。

> **方法论来源**：制作人设计哲学——"好游戏设计 = 给玩家创造丰富的情绪体验"。
> 致命缺陷特征："看起来完整但破坏了玩家情绪释放的周期性节奏。"

### 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 压力-释放周期 | 是否存在明确的压力期→释放期交替？ | P0 |
| 2 | 情绪维度覆盖 | 六大维度（目标感/新鲜感/成长感/社交压力/叙事性/随机性）覆盖了几个？目标感必须覆盖 | P1 |
| 3 | 成长波峰波谷 | 成长体验是否有起伏而非线性增长？ | P1 |
| 4 | 情绪平原检测 | 是否存在长时间（如连续2周+）无情绪波动的段落？ | P1 |
| 5 | 循环周期节奏 | 循环周期是否随时间合理拉长？ | P2 |
| 6 | 宏观期待感 | 是否定期给玩家新鲜的东西以塑造期待？ | P2 |

### 子代理 Prompt 模板

```
你是情绪节奏分析引擎（Rhythm Engine），负责审核策划方案的情绪曲线设计。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第1章"设计哲学"和第2章"成长节奏理论"。

核心理论：
- 前10分钟就要有"差一点挂了→质变→割草"的体验循环
- 循环周期逐步拉长，爽感不一定持续放大
- 宏观上需要压力期和释放期交替，定期注入新鲜内容塑造期待
- 致命缺陷 = 破坏情绪释放的周期性节奏

## 审核对象
[文档路径]

## 检查要求
1. 尝试绘制方案的情绪曲线（用文字描述各阶段的情绪起伏）
2. 识别压力期和释放期的分布
3. 检查六大情绪维度的覆盖情况
4. 标注可能存在的"情绪平原"段落
5. 评估成长体验的波峰波谷设计

## 输出格式
- 情绪曲线描述（各阶段的情绪起伏）
- 检查项表格
- 情绪平原标注（如有）
- 问题清单（带优先级）
- 维度评分（10分制）
```

### 输出格式

```markdown
### Rhythm 引擎检查结果

**情绪曲线概览**：
- 阶段1 [时间段]：[情绪描述] — [压力/释放/平原]
- 阶段2 [时间段]：[情绪描述] — [压力/释放/平原]
- ...

**情绪维度覆盖**：
- ✅ 目标感：[说明]
- ✅/❌ 新鲜感：[说明]
- ...（六大维度逐项）

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 压力-释放周期 | ✅/⚠️/❌ | ... |
| ... | ... | ... |

**⚠️ 情绪平原警告**（如有）：
- [时间段]：连续[X]无情绪波动，建议...

**维度评分**：X/10
```

### 边界条件

- 工具型/辅助型系统（如背包、设置界面）：不要求完整情绪曲线，标注"低置信度"
- 短期活动方案：压力-释放周期可在更短时间尺度上评估

## 维度3：红线与误区扫描（RedLine）

### 检查目的

检测方案是否触碰三条设计红线，是否命中五大常见设计误区。

> **方法论来源**：制作人红线——"核心循环不为KPI让步、不强迫玩家、不做冗余系统"。
> 高敏误区："设计给自己玩"——制作人原话："我经常会因为这条骂策划，很关注这条。"

### 红线检查（触碰即P0）

| # | 红线 | 检测方式 |
|---|------|---------|
| 1 | 核心循环被KPI污染 | 方案中是否有为短期指标（签到、体力卡点、每日任务强制等）破坏核心循环节奏的设计？ |
| 2 | 强迫设计 | 玩家在关键决策点是否有真实选择权？是否存在"不做X就玩不下去"的强制路径？ |
| 3 | 冗余系统 | 每个系统是否服务核心循环？能否回答"砍掉它，核心体验是否崩塌？" |

### 五大误区检测

| # | 误区 | 检测信号 | 严重度 |
|---|------|---------|--------|
| 1 | 堆系统当内容 | 系统数量多（>5个独立系统）但单个系统缺乏深度循环 | P1 |
| 2 | 数值解决体验问题 | 方案用奖励加码、数值调整来回应本质上是体验/节奏类的问题 | P1 |
| 3 | 过度参考竞品 | 大量引用"XX游戏有这个"但未论证自身核心循环为什么需要 | P2 |
| 4 | 前期过度披露 | 新手阶段（前30分钟/前7天）暴露的系统/概念/UI元素数量过多 | P1 |
| 5 | 设计给自己玩 | UE不直觉——需要大量文字解释才能理解、操作步骤繁琐、界面信息密度过高（**高敏，优先检查**） | P0 |

### 子代理 Prompt 模板

```

先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第7章"红线与误区"。

- "设计给自己玩"是最高敏误区，判断标准是UE是否直觉式、清晰易懂

- 误区检查表格

```

### 输出格式

## 维度4：价值冲突检测（Value）

### 检查目的

检测方案中是否存在低优先级目标压过高优先级目标的设计冲突。

> **方法论来源**：制作人价值排序——"公平感 > 社交生态 > 爽感 > 留存 > 付费"。
> 公平感定义："不是绝对数值平等，是感知层面的可接受度。"

### 排序基准

```
公平感（感知可接受度）
  > 社交生态（生态健康、中坚层稳定）
    > 爽感（情绪体验强度）
      > 留存（D1/D7/D30等指标）
        > 付费（收入、ARPU等）
```

### 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 排序违反 | 方案中是否存在为了提升低优先级目标（如付费）而损害高优先级目标（如公平感）的设计？ | P0 |
| 2 | 付费增量控制 | 付费玩家的每日增量是否在不让非付费玩家感到沮丧的范围内？ | P1 |
| 3 | 免费下限保障 | 免费玩家通过每天劳作，能否获取等价约20-50美金的付费产出？ | P1 |
| 4 | 逼氪检测 | 是否存在不符合本地消费习惯的强制付费设计？ | P0 |

### 子代理 Prompt 模板

```

- 价值目标识别
- 冲突点列表

```

### 输出格式

- 纯PVE方案：公平感检查放宽（无直接对抗场景）

## 维度5：玩家分层影响评估（Segment）

### 检查目的

评估方案对各正交维度玩家的影响，确保中坚层（承上启下的海豚层）被保护。

> **方法论来源**：制作人玩家模型——"四维正交分层，优先保护海豚+高活跃+强社交+中攻击性。"
> 保护原因："因为他们是一个承上启下的阶层。"

### 四维正交分层

| 维度 | 分层 |
|------|------|
| 付费能力 | 鲸鱼 / 海豚 / 免费 |
| 在线活跃 | 高 / 中 / 低 |
| 社交参与度 | 强 / 中 / 弱 |
| 社交攻击性 | 强 / 中 / 弱 |

### 关键评估对象

| # | 分层组合 | 评估重点 | 严重度（被忽略时） |
|---|---------|---------|------------------|
| 1 | 中坚层（海豚/高活跃/强社交/中攻击） | 是否被保护，体验是否正面 | P0 |
| 2 | 大R层（鲸鱼/任意活跃/任意社交） | 付费体验是否匹配投入 | P1 |
| 3 | 免费层（免费/任意活跃） | 是否有事干，是否感到被孤立 | P1 |
| 4 | 高攻击性玩家 | 是否有受限机制防止破坏生态 | P1 |
| 5 | 低活跃玩家 | 是否有追赶/回归路径 | P2 |

```
- 分层影响矩阵
- 问题清单（带优先级）

```

## 维度6：经济系统健康度（Economy）

### 检查目的

评估方案的经济系统是否存在通胀风险、重置策略是否合理、是否有追赶机制。

> **方法论来源**：制作人判断——"经济系统最难救，通胀一旦失控回收极难。"
> 重置策略："付费养成不重置只扩展，非付费可赛季重置，50%满级触发追赶+加层。"

### 检查项清单

| # | 检查项 | 判断标准 | 严重度 |
|---|--------|---------|--------|
| 1 | 通胀风险 | 资源产出是否有无限膨胀的可能？是否存在只产出不消耗的资源？ | P0 |
| 2 | 付费/赛季乘区分离 | 付费养成和赛季成长是否在不同乘区（乘法关系而非加法）？ | P1 |
| 3 | 追赶机制 | 是否存在后发玩家追赶先发玩家的路径？50%满级后是否有追赶设计？ | P1 |
| 4 | 重置策略合理性 | 付费养成是否不被重置？赛季重置是否仅影响非付费维度？ | P0 |
| 5 | 资源回收闭环 | 是否有消耗端平衡产出端？经济循环是否闭合？ | P1 |

### 子代理 Prompt 模板

```
你是经济系统健康度引擎（Economy Engine），负责评估方案的经济系统健康状况。

## 你的方法论
先阅读制作人方法论：[producer-methodology.md 路径]
重点关注第2章"成长节奏理论"中的重置策略决策树。

核心原则：
- 经济系统是最难救的系统，通胀一旦失控回收极难
- 付费养成绝对不重置，只能扩展或加新维度
- 非付费养成可以赛季重置，但成长和付费必须分属不同乘区
- 50%高活跃满级 → 先出追赶机制 → 一个月后加层级
- 数值膨胀可以通过多维度拆分包装来管理

## 审核对象
[文档路径]

## 检查要求
1. 识别方案中的所有资源类型和产出/消耗路径
2. 检查是否存在只产出不消耗的资源（通胀风险）
3. 检查付费养成和赛季成长是否分离
4. 检查重置策略是否合理（付费不重置）
5. 检查是否有追赶机制

## 输出格式
- 资源流向分析
- 检查项表格
- 问题清单（带优先级）
- 维度评分（10分制）
```

### 边界条件

- 非经济类方案（如UI设计、叙事方案）：整个引擎标注"不适用"
- 活动方案：只检查活动资源是否与主线经济系统冲突，不做完整经济分析
