### `/game.craft` 输出模板

craft 模式输出的功能文档遵循本文件第二部分「功能文档模板」的「通用部分 + 可选模块」结构。

**输出文件**：`output/craft-[活动名称]-YYYY-MM-DD.md`

输出时按以下流程生成：

1. **自动填写通用部分**（第1~10章），基于信息收集阶段获取的设计意图和框架定位
2. **根据活动类型自动启用可选模块**，参考模板附录的「模块选择速查」表
3. **附加审核通过记录**（craft 模式专属）
4. **文档完成后询问用户确认开发版本号**（如 v0.01），填入文档头部
5. **将最终文档保存到 `output/` 目录**，文件名格式：`craft-[活动名称]-YYYY-MM-DD.md`
6. **复制附件到 output 并嵌入引用**：将 `input/` 中的附件复制到 `output/assets/`，在文档中用相对路径引用：
   - 原型图/UI截图 → 第7章「交互设计」，用 `![描述](assets/文件名)` 嵌入
   - 动画/视频素材 → 第7章「动画资源需求」，用 `[描述](assets/文件名)` 链接
   - 数值表格 → 第5章「体力经济设计」
   - 竞品截图/录屏/其他附件 → 第10章「参考资料」
   - 这样 output/ 目录是自包含的，可以整个分享

## 【模块G】奖励仪式设计

**适用条件**：所有有关卡/阶段/轮次结算的活动。**本模块建议所有活动重点审查**——奖励呈现的仪式感直接影响玩家满足感和分享意愿。

> **教训**：Block 早期通关后只弹一个宝箱，玩家点开就结束，体验平淡。优化后改为：每关获得一个道具 → 通关一轮后12个道具逐步展示 → 最后打开宝箱 → 玩家可截图分享。奖励仪式感的提升直接改善了玩家体验。

### G.1 奖励节点梳理

列出活动中所有产生奖励的节点，并为每个节点设计呈现方式：

| 奖励节点 | 触发条件 | 奖励内容 | 呈现方式 | 仪式感等级 |
|---------|---------|---------|---------|-----------|
| 例：单关通关 | 完成一关 | 单个道具 | 道具飞入收集栏 | 轻量 |
| 例：一轮通关 | 完成全部关卡 | 累积道具+宝箱 | 道具逐个展示 → 宝箱开启 → 截图画面 | 重仪式 |
| | | | | |

### G.2 仪式感设计原则

- **逐步展示 > 一次性弹窗**：让玩家看到自己的收获逐步累积，而不是一个数字弹窗
- **最终画面要有截图价值**：玩家是否愿意把这个画面截图分享给朋友？
- **节奏递进**：小奖励轻量呈现，阶段大奖重仪式呈现，避免每次都重仪式导致麻木
- **收集感可视化**：如果活动有多关/多轮，让玩家看到"已收集 X/12"的进度条或陈列架
- **优先考虑AI生成视频（Seedance）**：用AI生成角色原画 + Seedance生成类CG短视频，替代传统的角色+Spine+特效流程。成本低、迭代快、品质感高于Spine动画，特别适合重仪式节点的通关演绎和每期更换的叙事内容

### G.3 仪式感审查清单

- [ ] 通关/结算时，奖励呈现是否超过"弹一个宝箱"的水平？
- [ ] 是否有逐步展示环节（而非一次性全给）？
- [ ] 最终结算画面是否有截图分享价值？
- [ ] 不同量级的奖励节点，仪式感是否有区分（小奖轻、大奖重）？
- [ ] 奖励呈现动画是否匹配活动主题？
